# Odoo Mentis — локальная разработка

Локальная копия боевого `odoo-host.pp.ua` (`jb@192.168.55.70`): Odoo 16.0,
PostgreSQL 15, база `mentis_dev`. Исходники взяты с сервера вместе с установленными
дополнительными модулями и отслеживаются в Git; базовые Docker-образы закреплены по digest.
Версии Python и системных библиотек контейнера отличаются от боевого Debian.
`docker/Dockerfile` устанавливает `pytz==2022.7.1`, как на сервере: исходный образ
содержит старый справочник без часового пояса `Europe/Kyiv`.

## Запуск

Требуются Python 3.12+, Docker Engine с Compose и SSH-доступ по ключу.
Для уже восстановленного экземпляра:

```sh
docker compose up -d
# Открыть http://localhost:8069
cat .local/credentials.txt
```

В базе два сайта: основной — `http://localhost:8069`, второй —
`http://site-2.localhost:8069` (если ОС не разрешает имя, добавьте его в `/etc/hosts`
для `127.0.0.1`).

Логин локального администратора: `localadmin`. Пароль создан случайно и хранится
в `.local/credentials.txt`. Боевые пароли и конфигурация на сервере не изменяются.
Остановка: `docker compose stop`. Логи: `docker compose logs -f odoo`.
`docker compose down` сохраняет данные; флаг `-v` удаляет локальные тома с БД и вложениями.

## Первичное создание копии

```sh
python3 scripts/init.py
docker compose build odoo
python3 scripts/snapshot.py
python3 scripts/restore.py
```

`snapshot.py` читает сервер через SSH, выполняет `pg_dump` и копирует filestore и
исходники. Пароль боевой БД используется только на сервере и не выводится.
Снимки сохраняются в `.local/backups/<UTC timestamp>/`, последний указан в
`.local/latest-backup`. Сервисы на сервере не останавливаются и не перенастраиваются.
База и filestore копируются последовательно: при одновременных боевых изменениях
это не единый атомарный снимок. Проверка восстановления проверяет наличие файлов
для всех сохранённых в БД вложений.

`restore.py [путь-к-снимку]` восстанавливает только новую `mentis_dev` и отказывается
перезаписывать существующую базу. Для повторного восстановления сначала отдельно
сохраните нужные локальные изменения и удалите локальную БД осознанно.

## Структура и разработка

- `addons/` — собственные модули; монтируются в `/mnt/extra-addons`.
- `source/odoo/` — точная копия установленного Odoo и модулей; доступна для отладки.
- `config/odoo.conf.example` — шаблон локальной конфигурации.
- `scripts/` — настройка, получение снимка, восстановление и проверки.
- `.local/` — снимки, локальные настройки и учётные данные; исключены из Git.
- Docker volumes `pgdata`, `odoo-data` — рабочая БД и filestore.

Исходники и `addons/` смонтированы с хоста, включён `--dev=reload,qweb,xml`.
После изменения manifest, моделей или схемы обновите соответствующий модуль:

```sh
docker compose stop odoo
docker compose run --rm odoo odoo -c /etc/odoo/odoo.conf -d mentis_dev -u my_module --stop-after-init --no-http
docker compose up -d web
```

Тесты конкретного модуля запускайте на отдельной тестовой БД/отдельном Compose-проекте
с `--test-enable --test-tags /my_module --stop-after-init`, чтобы не менять рабочую копию.

Проверка восстановленной среды:

```sh
python3 scripts/verify.py
```

Отчёт сохраняется в `.local/verification.json`: проверяются вход, страницы и ресурсы,
файлы вложений, отключённые интеграции и отсутствие исходящего доступа.

## Изоляция и данные

HTTP опубликован только на `127.0.0.1:8069`; PostgreSQL наружу не опубликован.
Контейнеры Odoo и PostgreSQL подключены только к Docker-сети `internal: true`, поэтому исходящие
подключения приложения к боевым сервисам и интернету заблокированы. Это также
отключает онлайн-платежи, SMS, IAP и внешние API при локальной разработке.
Входящие HTTP-запросы передаёт отдельный Nginx, подключённый к двум сетям;
он проксирует только в Odoo. Эта схема соответствует
[примеру разделения сетей Docker](https://docs.docker.com/engine/network/).
Браузер хоста этой сетью не ограничен: внешние ссылки/ресурсы в контенте могут
по-прежнему обращаться в интернет.

Перед запуском применяется штатная `odoo neutralize`, затем выключаются все cron,
почтовые серверы и входящая почта, отменяется очередь исходящих писем. URL сайта
заменяется на локальный, UUID базы меняется, у локального администратора сбрасывается
TOTP. Адрес `localadmin@example.invalid` предназначен только для разработки.

Копия содержит реальные данные и может содержать ключи интеграций. Не публикуйте
`.local/`, `.env`, дампы и исходный снимок; нейтрализация не является анонимизацией.
`AGENTS.md` сохранён без изменений.

## Git и боевой сервер

Ветки: `developement` — локальная разработка, `stage` — интеграция, `production` —
боевые релизы. Общий remote `origin`:
`https://github.com/astrix-z/odoo-mentis.git` (приватный репозиторий).
Прежний серверный remote сохранён локально как `server`.

Рабочая копия сервера готовится на `production`; подключение её к systemd требует
однократного запуска скрипта от root. Порядок переключения сервиса, продвижения
веток и обновления сервера описан в [deploy/README.md](deploy/README.md).
Отправка коммитов сама по себе не перезапускает боевой Odoo.
